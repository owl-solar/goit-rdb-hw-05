# Домашня робота №5: Узагальнені табличні вирази (CTE) та проєктування ознак для ML

Цей репозиторій містить рішення для п'ятого домашнього завдання з курсу роботи з реляційними базами даних та побудови пайплайнів обробки даних для задач Machine Learning.

---

## Технологічний стек
* **База даних:** PostgreSQL (з використанням `pgembed` / локального середовища виконання у Google Colab).
* **Мова:** Python (Pandas, SQLAlchemy).
* **Інструменти SQL:** Узагальнені табличні вирази (CTE), Рекурсивні CTE, Віконні функції (`Window Functions`), Матеріалізовані уявлення (`Materialized Views`), `EXPLAIN ANALYZE`.

---

## Структура та етапи виконання проєкту

### Завдання 1. Setup і typed-схема Olist
* Ініціалізація локального сервера PostgreSQL у середовищі виконання.
* Завантаження сирих даних електронної комерції (Olist) у проміжний шар (`_raw`-таблиці).
* Створення суворо типізованої реляційної схеми (`typed`-таблиці) з використанням обмежень `PRIMARY KEY`, `FOREIGN KEY`, `CHECK`.
* Перенесення даних за допомогою `INSERT ... SELECT` із корекцією назв полів та проведенням smoke-тесту рядків.

### Завдання 2. CTE-chain pipeline з ≥5 stages
* Побудова багаторівневого пайплайну вилучення ознак (feature engineering) для клієнтів із використанням логічно відокремлених етапів (`named stages`):
  * **RFM-ознаки:** розрахунок `recency_days`, `frequency` та `monetary` з використанням стабільної опорної дати (`reference_date`).
  * **Когортний аналіз:** визначення `cohort_quarter` на основі дати першої покупки.
  * **Ковзне середнє:** обчислення `avg_order_value_30d` через віконну функцію за 30-денний інтервал.
  * **Аналіз скасувань:** розрахунок показника `cancellation_rate` для кожного клієнта.
  * **Улюблена категорія:** визначення топ-1 категорії товарів за доходом (`preferred_category`) через ранжування `ROW_NUMBER()`.

### Завдання 3. Recursive CTE для referral chain
* Створення синтетичної таблиці рефералів `hw5_referrals` для зв'язків клієнтів.
* Реалізація рекурсивного запиту з anchor та recursive частинами.
* Реалізація надійного захисту від нескінченних циклів за допомогою масиву відвіданих ідентифікаторів (`path_ids`) та обмеження глибини рекурсії (`depth guard`).

### Завдання 4. Materialized View з CONCURRENT REFRESH
* Огортання повного CTE-пайплайну у матеріалізоване уявлення `mv_olist_customer_features`.
* Створення унікального індексу за полем `customer_id`.
* Виконання безпечного фонового оновлення даних за допомогою команди `REFRESH MATERIALIZED VIEW CONCURRENTLY`.

### Завдання 5. EXPLAIN ANALYZE + Reflection
* Збір планів виконання запитів за допомогою `EXPLAIN (ANALYZE, BUFFERS)` для повного переобчислення пайплайну та точкового пошуку за індексом.
* Порівняння продуктивності між «сирим» обчисленням (`Hash Join`, `Seq Scan`, тимчасові файли на диску) та доступом через індекси (`Index Scan`).
* Детальна рефлексія щодо вибору стратегій кешування, циклів оновлення матеріалізованих уявлень та компромісів між продуктивністю (*latency*) і актуальністю даних (*freshness*).
